Development Process

      
AI Choose Now! was built through an iterative, conversational development process between the author and Claude Opus 4.6. The entire application — backend, frontend, prompt engineering, and UI/UX — was developed through a series of natural-language prompts describing desired features, which the AI then implemented in code.


      
Key Prompts Used During Development


      

        1. Initial App Creation
        
Create a local "AI Dungeon" style adventure game using local ollama models, which are already installed: gemma3:4b for text-generation and x/flux2-klein:latest for image generation. The app is to be written in Python and will use Flask for the main interface. The interface should look modern and attractive, presenting the adventure text front-and-centre, with any choices generated by the AI presented as clickable buttons, and with the option to enter text to create one's own choice or words or actions to be incorporated into the text of the adventure. There should also be a button that can be clicked to generate an image based on the last paragraph of text.

The text of the adventure should generally only be two paragraphs in length, with the only exception being any setup needed at the very first prompt at the beginning of the adventure. It should always be written in second-person present tense, addressing the player as "You". Generated text should be streamed to the HTML page, so the user can read the text as it is being generated. Generated text should be stored locally so that the player can also press a button to see the entire adventure, including all choices made, in order, as though it's just one long story. There should also be a "download" adventure which saves the adventure as a single HTML page, including any images that have been generated.

Images should be generated using x/flux2-klein with a maximum resolution of 512 x 512, and should pop into the page when done.

An "Undo" button should also be available, which will remove the last generated text or image from the history.

Each time the user enters an action, all stored text of the adventure up to that point should be sent to the text-generation AI model, with the user's action being the last text sent. If the text is too long for the context window, a summary should be generated and stored and then used instead of the complete adventure text.

      


      

        2. Image Resolution & User Experience
        
Most of the application is working very well, but the image generation is defaulting to 1024 x 1024 instead of respecting the requested 512 x 512 resolution. This is important because generating full-size images (1024x1024) takes *much* longer than half-size ones. It would also be nice if the text-adventure was still playable while the image was generating, with the completed image popping into place, where requested, once it is done. (The image generating progress circle can stay there as a placeholder until the image pops in.) One minor feature request would be to get rid of the suggested choices from the generated text (and history) when the selection buttons are rendered.

      


      

        3. Download & Story Recording
        
Image generation is working now. The "Download" button does not download the entire story, though. In the test adventure I just played, only the last few actions and images and sections of generated text were included in the download - the first three sections were missing. Also, instead of the formula "You chose: Attempt to stop..." I would prefer, in the history/download/complete story record "You attempt to stop..." (i.e., "You <action>" instead of "You chose: <action>").

      


      

        4. Image & Paragraph Integration
        
Move the "AI Adventure" title to the left of the top frame, so the other buttons can float to the right of it, so that the whole top navigation takes up less vertical space. Eliminate the picture button next to the "Act" button and instead place small picture-frame buttons at the end of each paragraph, which the user can click at any time to generate an in-line picture that represents the text in that paragraph.

Each image generated should be placed so that it floats to the right of the paragraph it is depecting, the words wrapping around it. In order to better accommodate this arrangements, image size should be adjusted to 400 x 400 pixels.

Once a picture has been generated, replace the picture frame icon at the end of a paragraph with a "refresh" icon, which, if clicked will regenerate the picture for that paragraph, replacing the one previously generated from the paragraph text.

Add two buttons after the "refresh" icon, one red "x" for deleting the picture (which will restore the picture frame icon, allowing for no picture to be associated with the paragraph until the picture frame icon is clicked), and, before that, a pencil icon which will prompt the user with a text field so the user can add context to the paragraph text for the regeneration of the paragraph's picture.

      


      

        5. Local Network Access, Mobile View, and Scenario Essentials
        
Open the server to other devices on the local network.

Put the Full Story, Download, and New options into an expandible "hamburger" menu, and remove the text from the Undo button, with the intent of fitting the AI Adventure heading, undo button, and hamburger menu all on one line in mobile view so as to conserve vertical space.

Change the "Begin Your Adventure" prompt to a larger multi-line text-box, prompting the user for "scenario essentials" which will then be included in each prompt after the system text and before the history_text / user_message.

      


      

        6. Prompt Viewing & Text Editing
        
Add to the drop-down menu the ability to view the contents of the prompt variable, as it will be helpful to be able to see the entirety of the last prompt text submitted to the AI model.

Place a paper-and-pencil icon in the bottom right-hand corner of the last text-box, which, if clicked, will change to a save icon and allow the user to edit the text in-place. If the text is altered, any history entry stored should also be altered and the three AI-generated choices should disappear, leaving only the "Type your own action..." <Act> box.

Revise the opening screen so that the user is prompted for both scenario info and story starting text, and is provided with a way to save/load these to disk. The story starting text, if provided, should be used as the beginning of the story prompt and should be saved as the first entry in the story history.

      


      

        7. UI Refinements & Regeneration
        
Let's fine-tune a few things:
1. Review all prompts and all concatenation to produce prompts to make sure the actual, resultant prompts sent to the story AI are optimized to create an exciting, coherent, vivid, and immersive story experience for the reader that always produces only two paragraphs of text followed by three choices and that always aligns closely with what is specified in the scenario essentials.
2. Change the icon for adding context to the image regeneration from a pencil to a paintbrush. Also change the icon for editing the text of the story from a pencil to pencil-on-paper (same icon as is next to "last prompt" on the hamburger menu).
3. Add a "refresh" icon that floats to the left of the "undo" icon on the navbar. This icon should regenerate and replace the last section of the story from the last-specified action.

      


      

        8. Model Selection
        
Add a hamburger menu to the navbar of the opening page which shows the user what ollama model is currently selected for text-generation and allows the user to select a different model for text-generation from the available models installed on the user's computer, along with any necessary corresponding code that will enable text-generation with the selected model.

      


      

        9. Branding & Documentation
        
Change the name of the app from “AI Adventure” to “AI Choose Now!”, updating app and content as appropriate. Then create a GitHub Markdown README file outlining how to download and install the app on MacOS (and Linux/Windows, if that’s possible), and providing details about the process of developing the app. Finally, add the text of the main prompts used to create the app to an “About” page in the hamburger menu, along with the author (Edward Hewlett) and main AI used for development (Opus 4.6).
